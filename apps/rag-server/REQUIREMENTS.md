## 개요

minerva는 AI 에이전트와 개발 도구가 개발 문서를 검색해 활용할 수 있게 하는 RAG 서버다. Markdown 문서를 의미 단위의 청크로 나눠 색인하고, 질의와 관련된 청크 N개를 돌려준다. 답변은 만들지 않으며, 결과를 읽은 AI가 답을 합성한다.

**범위**

- 포함: RAG Server(`REQ-RAG`)의 요구. Console과 Backend의 요구는 각 앱 폴더의 `REQUIREMENTS.md`에 쓴다

**사용자**

| 사용자 유형 | 설명 |
| :--- | :--- |
| Backend | RAG Server를 호출하는 서버. 요약·캡션 생성, 색인, 검색, 문서 청크 조회, 평가를 요청하고, 문서 데이터를 소유한다 |
| 관리자 | Console에서 문서와 이름·판 정보를 관리하고, 용어집 파일을 고친다 |

## REQ 체계

- 기능 요구는 `REQ-RAG-{번호 경로}` 형식이다. `RAG`는 RAG Server의 접두사이고, 다른 앱은 각자의 `REQUIREMENTS.md`에서 자기 접두사(Console `FE`, Backend `BE`)를 쓴다
- RAG Server는 서버 앱이다. depth-1은 모듈, depth-2는 기능, depth-3은 검증 요구다. 기능 아래에 따로 검증할 하위 기능이 여럿이면 한 단계를 더 둔다. 기능 아래에 검증 요구와 하위 기능을 함께 둘 수 있다
- depth-1 노드 하나가 `ARCHITECT.md`의 단위 하나이고, `MODULE.md` 하나다. 진입점·서비스·공통·외부 자원 접근 같은 공용 모듈도 depth-1 노드로 둔다
- 서비스 모듈은 depth-2를 서비스 하나(색인 서비스, 검색 서비스 등)로 두고, 여러 서비스가 함께 쓰는 작업 관리도 depth-2로 둔다
- 진행 중이 아닌 마일스톤의 노드는 이름 뒤에 `(M-2)`처럼 표기하고, 표기가 없는 노드는 `M-1`이다. 진행 중인 마일스톤의 노드만 검증 요구까지 쓴다
- 요구 문장은 맨 아래 노드인 검증 요구만 가지며, 충족 기준과 테스트의 키가 된다
- 검증 요구의 「이력」 칸에는 그 요구가 추가·수정·폐기된 REV를 차례로 남긴다 (예: `REV-3 수정 · REV-5 폐기`). 문서를 처음 만든 REV는 「변경 이력」에만 남기고 이력 칸에는 적지 않는다. 이력 칸과 「변경 이력」의 기록은 지우거나 고치지 않고 계속 쌓는다
- 열거는 최소 목록이다. 닫힌 목록은 "다음만"이라고 쓴다
- 요구는 최소 기준선이다. 구현 세부(파일·헬퍼·내부 검사)가 늘어나는 것은 정상이며 REQ를 만들지 않는다. 사용자가 관찰할 수 있는 새 기능은 REQ를 추가해서만 들인다
- "설정한 값"은 RAG Server의 설정으로 바꿀 수 있는 값이다. 괄호 안의 기본값은 설정하지 않았을 때 쓰는 값이다
- ID는 바꾸거나 다시 쓰지 않는다. 지운 요구는 `폐기`로 표시하고 ID를 남긴다
- 이 문서는 사용자 승인으로만 바뀌며, 모든 변경은 「변경 이력」에 남는다

#### REQ-RAG-10.8 작업 관리

색인 요청은 작업으로 접수해 비동기로 처리한다. 작업 상태는 아래처럼 바뀐다. 실패한 작업은 RAG Server가 다시 시도하지 않으며, 관리자가 Console에서 사유를 읽고 조치하면 Backend가 색인을 다시 요청해 새 작업이 만들어진다.

```
색인 대기 ──▶ 색인 중 ──▶ 완료
    │            └──▶ 실패 (처리 실패, 서버 재시작)
    ├──▶ 대체됨 (같은 문서의 새 작업 접수)
    └──▶ 실패 (문서 삭제, 서버 재시작)
```

## 제약과 가정

- 제약: 모든 모델은 로컬에서 실행한다
- 제약: 모델은 Qwen3-14B(청킹·표 요약), Qwen3-VL-8B(이미지 캡션), Qwen3-Embedding-4B(임베딩), bge-reranker-v2-m3(재정렬)를 쓴다
- 제약: dense 검색과 BM25 키워드 검색의 순위는 RRF로 합친다
- 가정: Backend는 표·이미지 자리를 자리표시로 바꾼 색인용 MD와, 표·이미지별 요약·캡션을 함께 보낸다
- 가정: 검색 결과의 자리표시를 원래 표·이미지로 되돌리는 일은 Backend가 한다
- 가정: 문서 이름과 판 정보(판 표기, 판 날짜)는 관리자가 Console에서 정하고, Backend가 색인 요청에 담아 보낸다
- 가정: 골든셋과 평가 기록은 Backend가 저장한다

## 용어

대표어를 문서에서 쓰고, 동의어는 같은 뜻으로 읽는다.

| 대표어 | 동의어 | 뜻 |
| :--- | :--- | :--- |
| 청크 | chunk | 검색의 단위로 나눈 문서의 한 부분 |
| 본문 청크 | text 청크, text chunk | 문서 본문을 나눠 만든 청크. 표·이미지는 자리표시로 들어 있다 |
| 표·이미지 청크 | asset 청크, asset chunk | 표나 이미지 하나를 단독으로 검색하려고 따로 만든 청크 |
| 분할 조각 | 하위 청크, sub-chunk | 크기 상한을 넘는 청크를 다시 나눠 만든 청크 |
| 연관 청크 | related chunk | 같은 청크에서 나뉜 분할 조각, 또는 문서 안에서 바로 앞뒤에 있는 청크 |
| 자리표시 | 플레이스홀더, placeholder | 색인용 MD에서 표·이미지가 있던 자리에 들어간 표시. 표·이미지 ID와 설명을 담는다 |
| 색인용 MD | 색인용 사본, indexing MD | 원본 MD의 표·이미지를 자리표시로 바꾼 사본. Backend가 만든다 |
| 요약·캡션 | 힌트, hint, summary, caption | 표를 요약한 문장과 이미지를 설명한 문장 |
| 색인 텍스트 | indexing text | 청크의 자리표시를 요약·캡션 문장으로 바꾼 텍스트. 임베딩과 키워드 색인에 쓴다 |
| 헤딩 경로 | heading path | 청크가 속한 절까지의 헤딩을 차례로 이은 것 (예: 설치 > Docker > 환경변수) |
| 의미 단위 분할 | Agentic Chunking, 의미 분할, semantic chunking | LLM이 문서 구조와 문맥을 보고 청크를 나누는 방식 |
| 규칙 분할 | 헤딩 기준 분할, rule-based chunking | 헤딩 경계를 기준으로 청크를 나누는 방식 |
| 대체 분할 | fallback 분할, fallback chunking | 의미 단위 분할의 응답을 거듭 해석할 수 없거나 결과가 자리표시 보존 검증이나 경계 검증에 거듭 실패할 때 대신 쓰는 규칙 분할 |
| 경계 검증 | boundary validation | 의미 단위 분할이 정한 청크 경계가 원문을 빠짐·겹침·순서 바뀜 없이 나누고 코드 블록 중간을 자르지 않는지 확인하는 일 |
| 하이브리드 검색 | hybrid search | dense 검색과 키워드 검색을 함께 하고 순위를 합치는 검색 |
| 재정렬 | 리랭킹, reranking | 합친 후보를 재정렬 모델의 점수로 다시 정렬하는 일 |
| 버전 | 개정본, revision | 같은 문서를 고친 수정본. 새 버전이 이전 버전을 대체한다 |
| 문서 이름 | 이름, name | 문서를 부르는 이름. 이름이 같은 문서들은 같은 문서의 판들이다 |
| 판 | 에디션, edition | 같은 이름의 문서를 구분하는 판 표기와 판 날짜. 판이 다르면 별개 문서이고, 판끼리는 공존한다 (예: IEEE 1609.2.1의 2022판과 2025판) |
| 최신판 | latest edition | 같은 이름에서 검색되는 문서 중 판 날짜가 가장 늦은 판. 판 날짜가 같으면 모두 최신판이다 |
| 작업 | 색인 작업, job | 색인 요청 하나를 비동기로 처리하는 단위 |
| 체크섬 | checksum | 색인 입력과 색인 설정으로 만든 값. 값이 같으면 색인 결과도 같다 |
| 용어집 | 동의어 사전, glossary | 대표어와 그 동의어를 묶어 둔 목록 |
| 대표어 | canonical term | 용어집의 한 묶음을 대표하는 말 |
| 동의어 | synonym | 대표어와 같은 뜻으로 취급하는 한/영 단어 |
| 골든셋 | 정답셋, golden set | 질의와 정답을 짝지어 검색 품질을 재는 자료 |
| 검증 요구 | | REQ 트리의 맨 아래 항목. 요구 문장을 가지며 충족 기준·테스트와 연결된다 |
| 적중 | hit | 정답 원문 구간이 검색 결과에 전부 들어 있는 경우 |
