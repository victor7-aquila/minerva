## 개요

Console은 관리자가 문서를 올리고, 처리 상태를 확인하고, 실패를 조치하고, 골든셋으로 검색 품질을 확인하는 minerva의 관리용 웹 화면이다. Console은 Backend API만 호출한다. 문서 검색은 AI가 Backend의 검색 API로 하며, Console에는 문서를 찾는 검색창을 두지 않는다.

**범위**

- 포함: Console(`REQ-FE`)의 요구. Backend와 RAG Server의 요구는 각 앱 폴더의 `REQUIREMENTS.md`에 있다

**사용자**

| 사용자 유형 | 설명 |
| :--- | :--- |
| 관리자 | 문서를 올리고 이름·판 정보·요약·캡션을 고치며, 처리 상태와 로그를 확인하고, 골든셋으로 검색 품질을 잰다 |

## REQ 체계

- 기능 요구는 `REQ-FE-{번호 경로}` 형식이다. `FE`는 Console의 접두사이고, 다른 앱은 각자의 `REQUIREMENTS.md`에서 자기 접두사(Backend `BE`, RAG Server `RAG`)를 쓴다
- Console은 프런트엔드 앱이다. depth-1은 메뉴이고 메뉴 이름은 다루는 대상으로 짓는다. 하위 메뉴가 있으면 한 단계를 둔다. 그 아래에 메뉴에 속한 페이지를 형제로 두고, 메뉴를 누르면 가는 페이지를 첫 번째에 둔다. 페이지 아래에 기능과 `(모달)`을 두고, 그 아래가 검증 요구다
- 모달은 여는 화면의 하위 노드로 둔다. 여러 화면에서 여는 모달은 한 곳에만 두고 ID로 가리킨다. 확인 창은 노드로 두지 않는다
- 메뉴가 아니라 모든 페이지에 걸리는 공통 화면도 depth-1 노드로 둔다
- depth-1 노드 하나가 `ARCHITECT.md`의 단위 하나이고, `FEATURE.md` 하나다
- 진행 중이 아닌 마일스톤의 노드는 이름 뒤에 `(M-2)`처럼 표기하고, 표기가 없는 노드는 `M-1`이다. 진행 중인 마일스톤의 노드만 검증 요구까지 쓴다
- 요구 문장은 맨 아래 노드인 검증 요구만 가지며, 충족 기준과 테스트의 키가 된다
- 검증 요구의 「이력」 칸에는 그 요구가 추가·수정·폐기된 REV를 차례로 남긴다. 문서를 처음 만든 REV는 「변경 이력」에만 남기고 이력 칸에는 적지 않는다. 이력 칸과 「변경 이력」의 기록은 지우거나 고치지 않고 계속 쌓는다
- 열거는 최소 목록이다. 닫힌 목록은 "다음만"이라고 쓴다
- 요구는 최소 기준선이다. 구현 세부가 늘어나는 것은 정상이며 REQ를 만들지 않는다. 사용자가 관찰할 수 있는 새 기능은 REQ를 추가해서만 들인다
- "설정한 값"은 Console의 설정으로 바꿀 수 있는 값이다. 괄호 안의 기본값은 설정하지 않았을 때 쓰는 값이다
- ID는 바꾸거나 다시 쓰지 않는다. 지운 요구는 `폐기`로 표시하고 ID를 남긴다
- 이 문서는 사용자 승인으로만 바뀌며, 모든 변경은 「변경 이력」에 남는다

## 기능 요구사항

| ID | 이름 | 목적 | 마일스톤 |
| :--- | :--- | :--- | :--- |

| `REQ-FE-2` | 평가 | 골든셋을 쌓고 검색 품질을 잰다 | `M-1` |

## 제약과 가정

- 제약: Console은 Backend API만 호출한다
- 제약: 화면 문구는 한국어이고, 시각은 한국 표준시(KST) 기준이다
- 가정: 문서 상태(검색 상태, 처리 상태)는 Backend가 정하고 바꾼다. Console은 Backend가 준 상태를 보인다
- 가정: 골든셋과 평가 기록은 Backend가 저장한다. 골든셋 한 건의 지표는 RAG Server가 계산하고, 전체 요약(Hit@k 비율, MRR)은 Backend가 계산한다
- 가정: 문서 내용을 다시 올리면 Backend와 RAG Server 안에서는 새 버전이 되지만, Console은 버전을 보이지 않는다

## 용어

대표어를 문서에서 쓰고, 동의어는 같은 뜻으로 읽는다.

| 대표어 | 동의어 | 뜻 |
| :--- | :--- | :--- |
| 문서 | document | 관리자가 올린 MD 하나와 그 이미지들. 판이 다르면 다른 문서다 |
| 이름 | 문서 이름, name | 문서를 부르는 이름. 이름이 같은 문서들은 같은 문서의 판들로 묶인다 |
| 판 | 에디션, edition | 같은 이름의 문서를 구분하는 판 표기와 판 날짜. 판 정보가 없는 문서도 있다 |
| 최신판 | latest edition | 같은 이름에서 검색 가능한 문서 중 판 날짜가 가장 늦은 판. 판 날짜가 같으면 모두 최신판이다 |
| 같은 판 | same edition | 이름과 판 표기가 모두 같은 문서들. 판 정보가 없는 문서끼리는 이름만 같아도 같은 판이다 |
| 교체 | replace | 같은 판에 더 늦게 들어온(나중에 올리거나 그 판으로 바꾼) 문서가 검색 가능이 되어, 먼저 있던 문서가 검색에서 빠지는 일 |
| 검색 상태 | search state | 문서가 지금 검색에 쓰이는가. 검색 가능, 검색 안 됨, 교체됨 |
| 처리 상태 | processing state | 마지막으로 올린 내용을 어디까지 처리했는가. 업로드됨, 요약·캡션 생성 중, 색인 대기, 색인 중, 완료, 실패 |
| 재색인 | reindex | 마지막으로 올린 내용을 바꾸지 않고 다시 색인하는 일 |
| 요약·캡션 | 힌트, summary, caption | 표를 요약한 문장과 이미지를 설명한 문장. 만들지 못하면 임시 설명이 들어간다 |
| 원본 창 | 원본 보기, drawer | 화면 오른쪽에서 열려 문서 원본을 보이는 창 |
| 골든셋 | 정답셋, golden set | 질의와 정답(정답 문서, 정답 원문 구간)을 짝지은 평가 자료 |
| 적중 | hit | 정답 원문 구간이 검색 결과 N개 안에 전부 들어 있는 경우 |
| 놓침 | miss | 적중이 아닌 경우 |
| 정답 순위 | rank | 정답 구간을 담은 결과가 처음 나온 순위 |
| 포함 비율 | coverage | 정답 구간 중 검색 결과 N개에 들어 있는 비율 |
