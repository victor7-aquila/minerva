## 개요

Backend는 Console과 AI 에이전트·개발 도구의 요청을 받는 minerva의 진입점이다. 문서와 그 원본, 표·이미지, 요약·캡션, 골든셋, 로그를 저장하고, 요약·캡션 생성·색인·검색·평가 같은 연산은 RAG Server에 맡긴다. 대부분의 기능은 요청을 받아 RAG Server로 넘기고 결과를 저장하거나 복원하는 중계다.

**범위**

- 포함: Backend(`REQ-BE`)의 요구. Console과 RAG Server의 요구는 각 앱 폴더의 `REQUIREMENTS.md`에 있다

**사용자**

| 사용자 유형 | 설명 |
| :--- | :--- |
| Console | 관리자가 쓰는 화면. 문서·골든셋·로그를 다룬다 |
| AI 에이전트·개발 도구 | 검색 API를 호출한다 |
| RAG Server | 작업 상태 알림을 보낸다 |

## REQ 체계

- 기능 요구는 `REQ-BE-{번호 경로}` 형식이다. `BE`는 Backend의 접두사이고, 다른 앱은 각자의 `REQUIREMENTS.md`에서 자기 접두사(Console `FE`, RAG Server `RAG`)를 쓴다
- Backend는 서버 앱이다. depth-1은 모듈, depth-2는 기능, depth-3은 검증 요구다. 기능 아래에 따로 검증할 하위 기능이 여럿이면 한 단계를 더 둔다
- 진입점·공통·저장소·외부 서버 연동 같은 공용 모듈도 depth-1 노드로 둔다
- depth-1 노드 하나가 `ARCHITECT.md`의 단위 하나이고, `MODULE.md` 하나다
- 진행 중이 아닌 마일스톤의 노드는 이름 뒤에 `(M-2)`처럼 표기하고, 표기가 없는 노드는 `M-1`이다. 진행 중인 마일스톤의 노드만 검증 요구까지 쓴다
- 요구 문장은 맨 아래 노드인 검증 요구만 가지며, 충족 기준과 테스트의 키가 된다
- 검증 요구의 「이력」 칸에는 그 요구가 추가·수정·폐기된 REV를 차례로 남긴다. 문서를 처음 만든 REV는 「변경 이력」에만 남기고 이력 칸에는 적지 않는다. 이력 칸과 「변경 이력」의 기록은 지우거나 고치지 않고 계속 쌓는다
- 열거는 최소 목록이다. 닫힌 목록은 "다음만"이라고 쓴다
- 요구는 최소 기준선이다. 구현 세부가 늘어나는 것은 정상이며 REQ를 만들지 않는다. 사용자가 관찰할 수 있는 새 기능은 REQ를 추가해서만 들인다
- "설정한 값"은 Backend의 설정으로 바꿀 수 있는 값이다. 괄호 안의 기본값은 설정하지 않았을 때 쓰는 값이다
- ID는 바꾸거나 다시 쓰지 않는다. 지운 요구는 `폐기`로 표시하고 ID를 남긴다
- 이 문서는 사용자 승인으로만 바뀌며, 모든 변경은 「변경 이력」에 남는다

| `REQ-BE-1.2.7` | Console은 이름과 판 표기로, 업로드나 저장을 하면 같은 판이 되는 다른 문서들을 Backend에 물을 수 있다. | |
| `REQ-BE-1.2.8` | Backend는 문서가 교체됨이 되면 RAG Server에 그 문서의 청크 삭제를 요청하고(실패하면 `REQ-BE-1.8.4`와 같이 다시 요청한다), 그 문서의 남은 표·이미지 처리와 색인 요청을 하지 않는다. 처리 상태가 업로드됨, 요약·캡션 생성 중, 색인 대기, 색인 중이었으면 실패(사유: 교체됨)로 바꾼다. | |

## 제약과 가정

- 제약: Backend는 RAG Server와 MongoDB·파일 저장소만 쓴다. Qdrant에 직접 접속하지 않는다
- 제약: 예약 색인 일정(`REQ-BE-1.10.1`)은 cron 표현식으로 설정한다
- 가정: RAG Server는 색인·검색·요약·캡션 생성·평가 연산을 하고, 문서 데이터를 저장하지 않는다 (`apps/rag-server/REQUIREMENTS.md`)
- 가정: RAG Server는 작업 상태가 바뀔 때마다 Backend에 알린다 (루트 `INTERFACES.md` `IF-2`)
- 가정: 교체는 Backend가 남을 문서의 검색 가능을 알게 된 때 반영한다. RAG Server가 색인을 마친 때부터 그때까지(보통 알림 한 번, 알림이 끊기면 상태 맞추기 주기까지)는 같은 판 두 문서의 결과가 RAG Server 검색에 함께 나올 수 있고, Backend는 교체됨으로 바꾼 뒤부터 그 문서의 결과를 뺀다(`REQ-BE-4.2.2`)

## 용어

대표어를 문서에서 쓰고, 동의어는 같은 뜻으로 읽는다.

| 대표어 | 동의어 | 뜻 |
| :--- | :--- | :--- |
| 문서 | document | MD 하나와 그 이미지들. 판이 다르면 다른 문서다 |
| 버전 | 개정본, revision | 같은 문서를 다시 색인할 때마다 생기는 수정본(내용 다시 올리기, 요약·캡션 변경, 재색인). Console에는 보이지 않는다 |
| 이름 | 문서 이름, name | 문서를 부르는 이름. 이름이 같은 문서들은 같은 문서의 판들이다 |
| 판 | 에디션, edition | 같은 이름의 문서를 구분하는 판 표기와 판 날짜 |
| 최신판 | latest edition | 같은 이름에서 검색 가능한 문서 중 판 날짜가 가장 늦은 판. 같으면 모두 |
| 같은 판 | same edition | 이름과 판 표기가 모두 같은 문서들. 판 정보가 없는 문서끼리는 이름만 같아도 같은 판이다 |
| 교체 | replace | 같은 판에 더 늦게 들어온 문서가 검색 가능이 되어, 먼저 있던 문서가 검색에서 빠지는 일 |
| 검색 상태 | search state | 문서가 지금 검색에 쓰이는가. 검색 가능, 검색 안 됨, 교체됨 |
| 처리 상태 | processing state | 마지막 버전을 어디까지 처리했는가. 업로드됨, 요약·캡션 생성 중, 색인 대기, 색인 중, 완료, 실패 |
| 색인 대기열 | index queue | 예약 색인(`REQ-BE-1.10.1`)에서 요청할 문서 버전의 목록. 처리 상태가 색인 대기인 문서만 들어 있고, Backend가 다시 시작해도 남는다 |
| 표·이미지 | 자산, asset | 원본 MD 안의 표 하나 또는 이미지 참조 하나. 표 안의 이미지 참조는 따로 세지 않고 그 표의 일부로 본다 |
| 자리표시 | 플레이스홀더, placeholder | 색인용 MD에서 표·이미지 자리에 넣는 표시. 형식은 루트 `INTERFACES.md` `IF-1` |
| 색인용 MD | indexing MD | 원본 MD의 표·이미지를 자리표시로 바꾼 사본 |
| 요약·캡션 | 힌트, summary, caption | 표를 요약한 문장과 이미지를 설명한 문장 |
| 임시 설명 | fallback hint | 요약·캡션을 만들지 못했을 때 대신 쓰는 자리표시 설명 |
| 골든셋 | 정답셋, golden set | 질의와 정답(정답 문서, 정답 원문 구간)을 짝지은 평가 자료 |
| 평가 기록 | evaluation record | 골든셋 한 건을 한 번 평가한 결과 |
